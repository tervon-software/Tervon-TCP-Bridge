# M6 — действующий контракт Android Discovery и транспортного mTLS

**Решения пользователя от 2026-11-21 и уточнения 2026-11-22.** Архивные противоречивые схемы и устаревшие конкретные домены/порты удалены из этого действующего контракта. История решений сохранена в Git. Общий план: `docs/DEVELOPMENT_PLAN.md`.

## Назначение

Android Bridge передаёт **непрозрачный TCP-поток**, а Xray самостоятельно выполняет авторизацию VPN-протокола. Транспортный mTLS-сертификат Bridge **не требует проверки VLESS UUID, квоты, срока подписки или отдельной подписочной учётной записи**. Это прямое решение пользователя: не возвращать прежнее требование подписочной авторизации для выдачи сертификата. Наличие подписки/домена используется для определения, на каком сервере искать Bridge, не как секрет или криптографическое доказательство.

**Ограничение безопасности:** регистрация должна обслуживать только действительно настроенный сервер Bridge, проверять CSR и контролируемую доступность endpoint, ограничивать злоупотребления и атомарно активировать выданный сертификат в существующей ACL. Не выдавать сертификат неограниченному произвольному endpoint без дополнительных утверждённых мер; не вводить новую пользовательскую систему или собственную криптографию.

## Действующий автоматический сценарий

1. Пользователь **включает** тумблер «Обход DPI» в TervonVPN. Если он выключен — нет новых discovery/CSR запросов.
2. Android определяет **действующий HTTPS host выбранной подписки** из данных самого приложения, не из маскирующего XHTTP Host/SNI и не из зашитых доменов/портов.
3. Через существующий доверенный HTTPS discovery на этом сервере проверяется наличие Bridge. При отсутствии Bridge — нет регистрации и скрытой смены маршрута.
4. Для известного сервера при наличии сохранённого и действительного клиентского сертификата используется существующий сертификат. Иначе Android локально генерирует CSR из сохранённой индивидуальной P-256 identity и отправляет **только CSR**, не приватный ключ.
5. Существующий серверный `xui/enrollment_http.go` подписывает CSR через имеющийся client CA; `xui/enrollment_service.go` использует `IssueBridgeClientCertificate` без VLESS-подписочной авторизации. Регистратор подтверждает применение отпечатка сертификата через runtime ACL; отсутствие подтверждения — не успех.
6. Android проверяет доверие к серверному Bridge, получает проверенные транспортные параметры Bridge; отдельная `tcp_routes` отменена решением пользователя и не должна вновь появляться в Android; использует локальный Go Encapsulator для TCP, не создаёт дополнительный VPN или другой транспорт. Внутренний TCP-трафик Xray передаётся без модификации.
7. Переход между серверами/профилями использует согласованную автоматическую привязку. Не создавать ручных кнопок, новых trust-каталогов или протокольных фильтров без нового решения пользователя.

## Разделение данных

- **3x-ui API** предоставляет актуальную информацию о серверных inbound/протоколах/портах. Динамическая серверная маршрутизация требует сверки действующего состояния Xray и подтверждения поколения маршрутов Decapsulator; прежнюю `tcp_routes` не восстанавливать.
- **Discovery** публикует `remote_url`, `server_name`, публичные CA и необходимые транспортные параметры; старое поле `tcp_routes` не входит в утверждённый новый контракт.
- **server.json** хранит Bridge runtime policy, routes/ACL. Не является источником истины о протоколах 3x-ui; нельзя считать статическое считывание его портов выполнением API-first контракта.
- **Client CA private key / API Bearer tokens** остаются только на сервере; не выдаются Android, не пишутся в Git или диагностические события.
- **TLS**: обычный публично проверенный HTTPS для Discovery и отдельный TLS 1.3 + mTLS с ALPN h2 для транспортного Bridge. Два разных trust boundary.

**Открытая несовместимость GitHub:** в текущем `xui/cmd/m6-auto-registrar/main.go` сохранился legacy `configuredTCPRoutes()`, читающий `server.json`, несмотря на готовые API/reconcile функции. До проверки реального процесса/исходного commit на Homeserver не заявлять ни полностью автоматическую живую синхронизацию, ни необходимость писать серверный API заново.

**Стоп-линия:** этот документ не разрешает исправления Android, удаления классов, перезапуск Docker, Xray/3x-ui, создание новых ключей, смену подписей или ревизию утверждённого сертификатного алгоритма. Сначала инвентаризация actual source и согласование пофайловой замены Android-обвязки.
