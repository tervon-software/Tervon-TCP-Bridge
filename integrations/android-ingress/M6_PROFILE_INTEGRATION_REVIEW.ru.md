## Проверенные API

- `lib/features/home/home_screen.dart::_toggleConnection` проверяет выбранный профиль и вызывает `XrayService.saveDisplayedExternalNode`, затем `XrayService.start`; при запросе разрешений Android старт завершается асинхронно.
- `_chooseExternalServer` сначала вызывает `XrayService.saveDisplayedExternalNode`, затем (если подключён) `XrayService.restart`, после чего записывает `ExternalServerSelection.select` и обновляет UI. При ошибке пытается восстановить предыдущий профиль и выполнить обратный restart. Нельзя считать выбор успешно переключённым до прохождения транзакции.
- `_tervonChooseSubscription` останавливает текущий VPN, разрешает подписку и устанавливает выбранный узел (в том числе `null`).
- `ExternalServerSelection.selected(index)` возвращает сохранённый **полный URL VPN-узла**, а не адрес Bridge. `forNative` при замене URI иногда подбирает узел по совпадающему `uri.host`; эту эвристику нельзя использовать для установления доверия к Bridge.
- `BridgeControlChannel` предоставляет `getSettings`, `saveSettings`, `inspectCore`, `stage4IdentitySelfCheck`. Метод переключения сертификата отсутствует.
- `BridgeRuntimeControl` предоставляет `installClientConfig`, `start`, `stop`, `status`. `status.vpnRouteIntegrated=false` — фактический статус маршрутизации. Управление процессом не подключает Xray к локальному Bridge TCP.
- `BridgeConfigManager` хранит только один `bridge/config/bridge.json`; хранилища доверенных записей и независимых сертификатов серверов нет.
- `BridgeSettingsScreen` сохраняет флаг `enabled` через `BridgeRuntimeSettings`, но статус явно говорит, что трафик пока не переключается.
- `VpnForegroundService.startVpnInternal` поднимает TUN + HEV + libv2ray. Нельзя изменять это без точно проверенного способа перенаправления нужного Xray TCP-потока на локальный Bridge и защиты исходящего сокета от VPN-loop.

## Обязательный порядок работы в M6

1. Подготовить **доверенный** локальный каталог: стабильный идентификатор Bridge-сервера, допустимые VPN endpoint host:port, TLS-имя, подтверждённый endpoint регистрации. Не считать любое имя из произвольной подписки доверенным. Не выполнять DNS для идентификации.
2. Подготовить app-private хранилище сертификатов **по Bridge server ID**; серверный сертификат принимается только из явно инициированной пользователем и аутентифицированной процедуры регистрации. Проверить срок, цепочку и соответствие ключу устройства перед использованием. Не удалять сохранённые сертификаты при DNS-ошибке.
3. Подключить уже проверенный `BridgeServerReconciler` к событиям выбора профиля. Если ручной Bridge OFF — без Bridge-действий. Для ON: текущий известный — не трогать; другой известный с сохранённым сертификатом — выбрать; без сертификата — предложить кнопку ручной регистрации; неизвестный — Bridge OFF.
4. Реально перенаправить TCP-поток Xray к локальному Android Bridge и убедиться, что внешний HTTP/2 mTLS сокет защищён от VPN routing loop. Существующий механизм VpnService, HEV и Libv2ray не переписывать.
5. Для горячей смены профиля выполнять подготовку/проверку соответствующего Bridge-маршрута до того момента, когда перезапущенный Xray получает новый трафик. При ошибке откатить как VPN-конфигурацию, так и выбор Bridge. **Не добавлять только постфактум вызов после XrayService.restart.**
6. Для смены подписки, при которой VPN уже остановлен, привести Bridge к согласованному состоянию после определения выбранного узла, перед новым VPN start. Протоколы с несовместимым с TCP Bridge транспортом не маршрутизировать через Bridge.
7. Отдельные тесты: офлайн DNS, OFF без регистрационных запросов, A→B→A с двумя сохранёнными сертификатами, неизвестный сервер, отсутствие сертификата без автозапроса, ошибка restart с откатом, изменённый URI внутри той же подписки, повторная подписка без выбранного узла, реальный Android E2E.

**Не реализовано:** аутентифицированная выдача сертификата, доверенный каталог, app-private мультисерверное PKI, реальное Xray→Bridge перенаправление, socket protect, транзакционное переключение и Android E2E. **Подтверждено:** локальный Kotlin reconciler PASS на Homeserver. Действующие Linux Bridge, VPN, службы и APK не изменены.
