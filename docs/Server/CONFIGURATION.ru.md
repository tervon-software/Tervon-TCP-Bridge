# Конфигурация Tervon TCP Bridge v1.0.1

Схема соответствует [исходному коду v1.0.1](../prototype/cmd/bridge/main.go). Для первоначальной установки используйте [руководство v1.0.1](INSTALL-v1.0.1.ru.md) и шаблоны, создаваемые установщиком. Ниже — публичные примеры без адресов реальной инфраструктуры.

## Работа Bridge

Программа работает в двух режимах: `client` (Encapsulator, локальный TCP-вход) и `server` (Decapsulator, HTTPS/2+mTLS-приём и передача только в разрешённые TCP backend). Конфигурация — один JSON-файл, передаваемый через `-config /absolute/path/config.json`. Неизвестные поля, вторые JSON-документы и ошибочные параметры отвергаются.

| Поле | Режим | Назначение |
|---|---|---|
| `mode` | оба | `client` или `server` |
| `listen` | оба | адрес прослушивания `host:port` |
| `cert_file`, `key_file`, `ca_file` | оба | файлы PKI, отдельные для каждой роли |
| `remote_url` | client | HTTPS URL с путём **`/v2/stream`** и без query/fragment |
| `server_name` | client | проверяемое DNS-имя TLS-сертификата сервера |
| `service` | client | разрешённый сервис, например `vpn` |
| `max_local_connections` | client | **`0` — без фиксированной программной квоты TCP-сессий** |
| `routes` | server | сервис → список `{"Name":"...","Address":"host:port"}` |
| `authorized` | server | SHA-256 DER клиентского leaf-сертификата → допустимые сервисы |
| `max_streams` | server | **`0` — без фиксированной программной квоты HTTP/2-потоков** |
| `padding_enabled` | оба | Padding |
| `padding_rate_enabled` | оба | адаптивный Rate Padding, требует Padding |
| `jitter_enabled` | оба | адаптивный Jitter, требует Rate Padding |
| `metrics_listen` | оба | необязательный адрес приватной метрики, только буквальный IP loopback |

В официальной конфигурации v1.0.1 `max_local_connections=0` и `max_streams=0`. **Не устанавливайте произвольные квоты**, предполагая количество подключений пользователей. Ноль снимает только встроенный фиксированный предел: файловые дескрипторы, память, CPU и сетевые ресурсы ОС по-прежнему конечны. Отрицательные значения недопустимы.

Параметры Padding/Rate Padding/Jitter должны быть согласованы между сторонами; примеры из установщика включают все три. Bridge не декодирует VLESS, Trojan или Shadowsocks и сам не реализует отдельный UDP-транспорт.

## Образцы JSON

- [Пример клиента](../examples/client.json)
- [Пример сервера](../examples/server.json)

Для новых установок предпочтительнее `/etc/tervon-tcp-bridge/client.json.example` и `server.json.example`, созданные установщиком v1.0.1: они соответствуют выпущенному бинарнику. Реальные домены, сертификаты и сервисы вы задаёте самостоятельно.

Сервер `routes` формирует из доверенной локальной конфигурации, а не из входящего запроса клиента; при нескольких backend применяется выбор по кругу с попыткой следующего адреса после неудачного TCP dial. Это не миграция уже открытого соединения. Сервер проверяет валидный клиентский TLS-сертификат и разрешённость service, клиент проверяет TLS-имя сервера; TLS 1.3 и ALPN `h2` обязательны.

## Метрики

Если `metrics_listen` задан как loopback `127.0.0.1:<port>`, доступны приватные `GET /metrics/v1` (JSON) и `GET /metrics` (Prometheus). Мониторинг хранит агрегатные счётчики сессий, полезных байтов, ошибок, Padding/Jitter, готовности и ресурсов. Он не требует публикации внутреннего VPN-трафика. Не открывайте endpoint метрик в Интернет.

## Безопасность и ограничения

- Сохраняйте CA private key отдельно от серверов. Файлы `client.key` и `server.key` должны быть доступны только соответствующей службе.
- Ограничивайте входящий порт `server` брандмауэром и используйте разрешённые сертификаты; предпочитайте loopback для внутреннего TCP-входа `client`.
- Не выкладывайте реальные адреса серверов, пользовательские токены, UUID, приватные JSON, сертификаты или ключи в публичный GitHub.
- Не запускайте `install/install-bridge.sh` поверх работающего Bridge: скрипт предназначен для **первоначальной** установки на чистый сервер и откажется перезаписывать существующие файлы.
- Агрегатные метрики не доказывают отсутствия starvation для каждого потока, гарантий сетевого RTT или прохождения любых сетевых фильтров.

По вопросам первоначальной установки и диагностики смотрите [INSTALL-v1.0.1.ru.md](INSTALL-v1.0.1.ru.md) и [TROUBLESHOOTING.ru.md](TROUBLESHOOTING.ru.md).
