# Установка Tervon TCP Bridge M6 для Android

Единый интерактивный установщик для нового Decapsulator и Registrar на Linux x86-64 с systemd. Он использует опубликованное ядро `tervon-bridge-linux-amd64-v1.0.2-m6` после проверки SHA-256 и собирает Registrar из исходников этой ветки.

## Перед запуском

- На сервере работают Xray с локальным API и панель 3x-ui или Remnawave. Registrar должен видеть живой Xray: штатный пробник ищет Xray как дочерний процесс указанной службы systemd. Если узел упакован иначе, сначала проверьте, что этот способ наблюдения подходит.
- HTTPS-подписка уже обслуживается nginx. Нужен путь к исходному файлу её HTTPS-блока с явными `server_name` и `listen … ssl`. Установщик использует уже действующий публичный сертификат nginx и создаёт отдельные CA и сертификат TLS для транспорта Bridge.
- Нужны Python 3.11+, Go 1.23+, OpenSSL, nginx, curl, systemd, iproute2, procps и util-linux. Для Docker дополнительно нужны Docker Engine и Compose v2. Нативный режим запускает ядро от UID/GID 65532.
- Внешний TCP-порт Bridge открыт в правилах сети. Для Docker Xray принимает подключения с адреса, доступного из контейнера через `host.docker.internal`. Для нативной установки укажите IP слушателя Xray на хосте, например `127.0.0.1`.
- API-токен панели требуется только на сервере. При штатной схеме Discovery публичный HTTPS проксирует запрос CSR на Registrar, который проверяет CSR и точное подтверждение ACL. Право на VPN-подписку при выдаче транспортного сертификата отдельно не проверяется.

## Запуск

```bash
git clone --branch work/m6-android-ingress git@github.com:tervon-software/Tervon-TCP-Bridge.git
cd Tervon-TCP-Bridge
sudo ./install.sh
```

Наберите `native` или `docker`. Укажите домен и **фактический внешний HTTPS-порт** подписки, локальный порт Registrar, домен и внешний порт транспорта, тип панели и её HTTPS API, systemd unit и имя бинарника Xray. Для Remnawave укажите UUID обслуживаемой ноды. Если внешний порт подписки преобразован на пути к nginx, укажите также фактический порт `listen` в её HTTPS-блоке. Токен вводится скрыто после подтверждения установки.

`sudo ./install.sh --check` проверяет исходные условия и собирает nginx-кандидат в памяти. Команда не записывает файлы и не запускает службы.

| Выбор | Decapsulator | Registrar |
| --- | --- | --- |
| `native` | Постоянная служба `tervon-m6-decapsulator.service`. | Проверяет процесс, исполняемый файл и SHA-256. Подтверждает поколение по журналу systemd. |
| `docker` | Compose, запускаемый постоянной службой `tervon-m6-compose.service`. | Определяет актуальный ID по имени контейнера при запуске и подтверждает поколение по журналу контейнера. |

Оба варианта включают `tervon-m6-auto-registrar.service` в автозапуск. PKI и настройки лежат в `/etc/tervon/bridge-android`, бинарники и Compose — в `/opt/tervon-bridge-m6`. Закрытые CA и токен панели остаются в `private/`.

Скрипт добавляет точный маршрут Discovery в выбранный HTTPS-блок nginx, проверяет синтаксис и перечитывает конфигурацию. Исходная версия сохраняется в `private/nginx-vhost.before.conf`. Если проверка или перечитывание nginx завершается ошибкой, скрипт восстанавливает прежнюю конфигурацию. Скрипт предназначен для **новой** установки. При обнаружении существующих путей или служб он останавливается. Для миграции действующей установки используйте её отдельный порядок обновления.

После запуска скрипт проверяет Discovery по указанному **внешнему URL**. Для `M6_INSTALL=PASS` он должен получить `available: true`, ожидаемый адрес транспорта и публичный CA именно этой установки. Если сервер не может обратиться к своему публичному адресу, скрипт выдаст `M6_INSTALL=UNVERIFIED`. Проверьте адрес извне и включите мост на Android. Успешная установка на сервере не заменяет проверку трафика Android.

## Статус проверки

Оба режима проверены на тестовых конфигурациях и имитированных командах, включая нестандартный порт Discovery и отсутствие Docker-вызовов в нативном режиме. Go-тесты, vet и сборка Registrar прошли. Реальная чистая установка с systemd, nginx, Xray и Android, а также повторный запуск после перезагрузки остаются отдельной приёмкой.
