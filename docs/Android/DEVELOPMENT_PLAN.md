# Tervon TCP Bridge — Android: разделы утверждённого плана

> Разделено по запросу владельца из ранее единого документа. Все исходные строки сохранены в Server/Android документах, история commit не изменена. Области PASS действуют только на соответствующие испытания.

### Обязательная формула Android M6 (прямое решение оператора 2026-11-22)

**Android TervonVPN → существующий Go Encapsulator → HTTPS/2 + TLS 1.3 + mTLS → серверный Decapsulator → Xray.**

**Статус: УТВЕРЖДЕНО, НЕ ИЗМЕНЯТЬ БЕЗ СОГЛАСИЯ.** Android выполняет только интеграцию существующего Go Encapsulator с TCP-подключением TervonVPN, автоматическое получение уже предусмотренного клиентского сертификата/ключа и доверенных транспортных параметров, установку mTLS HTTP/2 соединения и двунаправленную прозрачную передачу байтов. Непрозрачный `service` является параметром запроса существующего Bridge-протокола, **не** таблицей маршрутов на Android.

**Разделение ответственности:** серверный Bridge самостоятельно управляет TCP backend, согласованной маршрутизацией, 3x-ui/Xray и RuntimePolicy. Не переносить `ConfirmedRouteStore`, `SyncVerifiedRoutes`, 3x-ui API, список backend-портов, policy generation ACK или server routing в Android; не создавать второй Android-маршрутизатор, серверный API или параллельный lifecycle. Не изменять рабочий Linux v1.0.1/v1.0.2, Finserver, Homeserver, Docker, сертификатную инфраструктуру и текущую публикацию без отдельного согласования.

**Критерий готовности M6:** реальная передача TCP-данных в обе стороны и работа интернет-соединения через выбранные подтверждённые TCP-профили; успешная компиляция, выдача сертификата или запуск локального listener сами по себе PASS не означают.

### M6 — Android (только после M5)
**Пакет:** аудит TervonVPN VpnService и ядра, поддерживаемый способ переиспользования Bridge, защищённое хранение ключей, защита сокетов от VPN-loop, переключатель «Обход DPI», тесты мобильных сетей. Без изменения действующего APK до отдельного решения.

**Уточнение текущих статусов на 2026-11-22:** M0–M5 и Linux v1.0.1 имеют ранее полученные операторские результаты, см. соответствующие commit и журнал; не путать их с сегодняшним M6. ## Текущий модуль M6 — восстановление Android-обвязки, решение пользователя 2026-11-22

**Цель:** инвентаризировать зависимые Android Kotlin/Dart/Go-файлы; затем согласовать перечень удаляемых/очищаемых ошибочных файлов и пересоздать именно **Android-обвязку**, не добавляя параллельную обвязку поверх старой. Никаких правок самого приложения, его APK, подписи, рабочих Docker/Xray/3x-ui/Bridge, пока инвентаризация и список замены не согласованы.

**Утверждённое:** прозрачный TCP, автоматическое определение активного сервера из текущей HTTPS-подписки, утверждённые enrolment/PKI/mTLS, существующий серверный API и маршруты. Не создавать второй серверный API. Не зашивать реальные домены, backend-порты, service names, protocol allowlist и назначения. Android берёт назначение из активного TCP-профиля, защищённые параметры Bridge — из доверенного Discovery. Не раскрывать ключи, токены, URLs и содержимое потока в логах. Обработка ошибок должна обозначать конкретную стадию отказа; нельзя молча терять stdout/stderr или объявлять локальный listener успешной end-to-end передачей.

**Контракт управления (уточнение 2026-11-22; отменяет старые `tcp_routes`):** утверждённым источником актуальных TCP inbound/портов служит **3x-ui API**, с независимой сверкой текущего применённого Xray; отдельную `tcp_routes` не создавать и не восстанавливать: её исключение утверждено пользователем 2026-11-22; актуальные входы и порты поступают из 3x-ui API, с подтверждением применённого Xray. `config/server.json` является конфигурацией Bridge (маршруты и ACL конкретного поколения), **но не справочником протоколов 3x-ui и не первоисточником их актуальных портов**. **Legacy `configuredTCPRoutes` и его статическая публикация удалены из GitHub source** (commit `f5d70c5`, исправление синтаксиса `1151816`, подтверждённые Go tests `1fa836c`). **Регистрация Android не зависит от поколений серверной маршрутизации:** Discovery возвращает только необходимые параметры защищённого соединения, POST CSR выдаёт сертификат исключительно после успешной активации ACL. Связка `BridgeEnrollmentHTTP` с пустым `ConfirmedRouteStore` удалена из GitHub source как ошибочная. Старый `tcp_routes` не возвращать. Исторический запущенный регистратор не изменён; восстановленный код нельзя считать production PASS без реальных проверок регистрации. В GitHub уже есть `xui/inbounds.go`, `route_reconcile.go`, `route_sync.go`, `confirmed_routes.go`, `policy_generation.go`, `policy_docker_confirm.go`; не писать их заново. **Серверный API→Xray→RuntimePolicy конвейер остаётся самостоятельным механизмом сервера и не является условием выдачи Android-сертификата.** Фактическое развёртывание не менялось. Нельзя выдавать существование функций за работающую автоматическую синхронизацию.

**Известный рабочий источник Android:** пользовательский исходный Android проект на Homeserver `/opt/tervonvpndpi`; отдельно проверенные в этой переписке Kotlin диагностика и Go ARM64. Изолированное Go диагностическое ядро SHA256 `a7f693981f111436cd0023ced47417b9f7f222df33a60c319c1a4b073acefccd`; установка в source `jniLibs/arm64-v8a` PASS; Gradle Kotlin compile PASS. Пользователь собрал и установил APK; реальный XHTTP: повторные `EOF`, `127.0.0.1` reset, Bridge `UNKNOWN`, **ИНТЕРНЕТА НЕТ**, `ANDROID_E2E=FAIL`. VLESS TCP/Trojan E2E тоже не подтверждены. Никакой root cause серверного ACL или порта без телеметрии не объявлять.

**Инвентаризация GitHub и предоставленного исходного архива завершена 2026-11-22.** Согласованная пользователем область следующей работы внутри M6: `BridgeVpnSession.kt`, `BridgeXrayConfigRoute.kt`, `BridgeVlessRoutePlan.kt`, `BridgeRuntimeControl.kt`, `BridgeControlChannel.kt`, `BridgeCoreManager.kt`, `BridgeConfigManager.kt`. Для каждой позиции в `docs/M6_AUDIT_2026-11-22.md` записаны текущие зависимости и SHA256 архивного снимка. Действующий Android-проект после диагностического обновления на Homeserver не сверялся: перед записью в приложение обязателен read-only preflight актуальных целевых исходников и call-sites. Не подменять этот пробел прежним архивом. Удаление/очистка только внутри утверждённой семёрки и по реальным зависимостям, без второго lifecycle и без изменения сохранённых Go/server/API/PKI механизмов.

**Следующий шаг:** M6 Android wrapper rebuild — сначала реальный current-source preflight; далее минимальная реализация одного пути управления и прозрачного TCP в пределах семи файлов, затем комплексные тесты. Окончательный PASS — двунаправленный TCP E2E, VLESS TCP/XHTTP/Trojan и действительный интернет; компиляция или локальный listener отдельно недостаточны.
