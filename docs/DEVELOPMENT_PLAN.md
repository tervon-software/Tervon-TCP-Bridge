## Неприкосновенная область — Linux Bridge

- Сохраняются Linux Bridge v1.0.1 и v1.0.2, их релизные материалы, исходники, настройки и эксплуатационные механизмы.
- Linux v1.0.2 использует RuntimePolicy (атомарное применение `routes + authorized`); исходники и воспроизводящие скрипты в `integrations/android-ingress/runtime-acl/` сохранены, несмотря на историческое имя каталога. `runtime-routes/` также оставлен для предотвращения незапрошенной смены Linux-серверной функциональности.
- Существование исходного кода, записи в журнале или результата CI само по себе не означает успешный текущий runtime/E2E. Статусы и хеши релиза проверять по GitHub Release и привязанному commit, прежде чем использовать.
- Не менять релизы, подпись, работающие службы, Docker, Xray, PKI и установки на Homeserver без отдельного решения.

**M6 Android: СБРОШЕНО / НЕ РЕАЛИЗОВАНО / PASS НЕ ПОДТВЕРЖДЁН.** По прямому решению пользователя удалены связанные с мобильной интеграцией исходники из этой ветки, включая `m6-auto-registrar`, enrollment, catalog/discovery, Android route wrappers и документацию, представлявшую эту реализацию как рабочую.

Удаление файлов из ветки не означает деинсталляцию на сервере или телефоне; реальное состояние Homeserver и Android-приложения в ходе этой очистки **не проверялось**. Никаких утверждений об удалении установленных служб, APK или PKI не делать.

## Сохраняемый контракт Linux-транспорта

Bridge передаёт двунаправленный непрозрачный TCP-поток. TLS/mTLS использует заранее подготовленные клиентский сертификат и закрытый ключ, доверенный CA и разрешённые сервером сертификаты; это свойство существующего Linux Bridge, а не созданной M6 регистрации. Никакой регистрации Android-устройства при запуске Linux-транспорта не требуется.

## Правила дальнейшей работы

1. Разработка только после нового, явно согласованного задания. Самостоятельно назначать M6, восстанавливать удалённую обвязку или менять архитектуру запрещено.
2. До изменений сверять живой GitHub HEAD, исходники, release tag, документацию и результаты конкретных тестов. Устаревшие записи журналов — история, не действующий контракт.
3. Соблюдать последовательность: один модуль → согласованная реализация → проверки → исправления → подтверждённый PASS → документация → commit.
4. Отделять статусы ПРЕДЛОЖЕНО, СОГЛАСОВАНО, РЕАЛИЗОВАНО, ПРОТЕСТИРОВАНО, PASS и ВЫПУЩЕНО; не сообщать об удалении, тестировании или выпуске без проверенного доказательства.
5. Git по SSH; GitHub API допускается для чтения и записи. Работающие службы не трогать.
